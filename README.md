# Bottomless

Your whole photo library in your own cloud storage, browsable on the iPhone (even offline), with old photos removed
from the phone once they are safely backed up. See [DESIGN.md](DESIGN.md) for how it works and why.

```
backend/   Cloudflare Worker (TypeScript): API, change feed, share links, nightly cleanup. D1 + R2 + GCS.
ios/       SwiftUI app (Xcode project generated by XcodeGen from ios/project.yml)
  Packages/BottomlessCore   API client, catalog (SQLite), sync, cache, backup pipeline, hashing, thumbnails
scripts/   setup_cloud.sh, local_backend.sh, test_core.sh, smoke.mjs, make_media.swift
```

Live API: `https://bottomless-api.<your-subdomain>.workers.dev` (token in `.secrets/app_token`, never committed).

## Install on your iPhone (free Apple ID, no App Store)

1. Plug the iPhone into the Mac with a cable and unlock it. Tap **Trust** on the phone.
2. On the iPhone: **Settings → Privacy & Security → Developer Mode → On** (it restarts).
3. In Xcode: **Settings → Accounts → +** → sign in with your Apple ID. A "Personal Team" appears.
4. Quick path: run `scripts/install_phone.sh`. It finds the phone and your Personal Team, then builds, signs,
   installs and launches the app. Or do it by hand in Xcode: open the project and pick your phone and team:
   ```bash
   open ~/bottomless/ios/Bottomless.xcodeproj
   ```
   Select the **Bottomless** target → **Signing & Capabilities** → Team: *(Your Name) (Personal Team)*.
   If Xcode says the bundle id is taken, change `BOTTOMLESS_BUNDLE_ID` in `ios/Config/Bottomless.xcconfig`
   (e.g. `com.shaunakkapur.bottomless2`) and pick the team again.
5. Choose your iPhone in the device menu at the top and press **Run** (▶).
6. First launch on the phone: **Settings → General → VPN & Device Management → your Apple ID → Trust**, then open
   Bottomless again and allow **Full Access** to Photos.

The free signature lasts 7 days. Press Run again (phone on the same Wi‑Fi works after the first cable install), or
install **SideStore**/**AltStore** to renew it automatically. Your photos and the app's data are kept when it renews.

### Daily backup you can rely on
Shortcuts → Automation → **+** → *Charger* → *Is Connected* → **Run Immediately** → action **Sync Photos (Bottomless)**.
The app also syncs whenever you open it, and iOS runs a nightly backup while charging.

### Live Photos
Press and hold a Live Photo to play its motion (the clip downloads once, then plays from the iPhone). The **LIVE**
menu at the top of the viewer plays it or turns Live **Off** for that photo, which keeps it still everywhere you use
Bottomless; the motion clip is kept, so you can turn it back on. To show every Live Photo as a still, turn off
**Play Live Photos** in the Backup tab's settings.

### Free up space
Turn off iCloud Photos first (Settings → your name → iCloud → Photos), then in Bottomless → **Backup** → turn on
"iCloud Photos is turned off" → **Free up space**. Only photos that are backed up, older than the keep window
(default 30 days) and not favorites are removed; iOS asks you to confirm and keeps them in Recently Deleted for 30 days.

## Cloud

```bash
scripts/setup_cloud.sh gcs    # originals in Google Cloud Storage Archive (~$1.44 per 100 GB-year, what is deployed now)
scripts/setup_cloud.sh r2     # originals in Cloudflare R2
```
Re-running is safe. The GCS mode needs `gcloud auth login` and billing on the `bottomless-512607` project. After
switching modes, rebuild the app only if the API URL changed (it does not).

## Bring in Google Photos

Export the account at takeout.google.com (Deselect all → Google Photos → 2 GB zips), download the parts, then:
```bash
scripts/import_google_photos.sh <account-name> ~/Downloads/takeout-*.zip
```
Capture time, location and favorites come from Google's JSON files (falling back to the photo's own EXIF), Live
Photos stay paired, album copies are not uploaded twice, and files Apple cannot decode still get their original backed
up behind a plain tile. Google often puts a photo and its JSON in different zips; the importer remembers every JSON it
has seen and fixes the date and place once the matching one arrives, so parts can be imported in any order. Each zip
is deleted after a verified extraction. Use a different `<account-name>` per Google account. Live and Motion Photos
whose photo and clip landed in different zips are joined back into one Live Photo once both halves are in.

## People

Collections has a People row like Photos: tap someone to see every photo they are in, name them, merge two groups that
are the same person ("Same Person As…"), or hide someone. In a photo's Info, "This Is Someone Else…" moves it to the
right person (or a new one) and "Not <name>" takes it out.

The phone has no public face recognition API, so the recognizing runs on GitHub Actions' free Linux runners, every 6
hours, from a separate private repo (its secrets reach every photo, and anyone with write access to a repo can read
its Actions secrets):
```bash
scripts/faces_cloud.sh deploy     # create/update shaunak1206/bottomless-faces from faces-runner/ and scripts/faces.py
scripts/faces_cloud.sh run 4      # run now; 4 parallel index jobs for a big backlog (1 is the default)
scripts/faces_cloud.sh status
```
`faces.py` downloads each photo's 2048 px preview, finds faces with InsightFace's SCRFD detector, embeds them with
ArcFace (models from InsightFace's `buffalo_l` release, cached by Actions) and groups the embeddings. Only face boxes
and the grouping go to D1; the embeddings live in `.faces/index.sqlite`, which the runner keeps in R2
(`/v1/faces/state`) between runs. Each run only looks at photos it has not seen, so new photos backed up from the phone
are sorted into People on the next run: faces join the person they look most like, and faces that match nobody form
new people once three of them agree. Names, merges and corrections made in the app are never undone by a later run.
It also runs on a Mac (`scripts/faces.py`, Core ML; `scripts/faces_agent.sh install` for every 30 minutes).

## Tests

```bash
cd backend && npm test                       # 32 API tests (local Worker + S3 imitation, spending caps, people)
scripts/test_core.sh                         # app core end-to-end against a local Worker, R2 and S3 modes
cd ios/Packages/BottomlessCore && swift test --skip IntegrationTests   # 28 unit tests
node scripts/smoke.mjs $(cat .secrets/api_url) .secrets/app_token      # live checks against the deployed API
```
UI tests drive the app in the simulator (see `docs/screenshots/` for what they capture): library, viewer, favorite,
share link, backup status, offline, Free up space with the iOS delete prompt, and a Live Photo playing, turned off and
shown as a still. One script starts a local backend, installs the app fresh, adds a sample camera roll, seeds a
cloud-only Live Photo and runs all four:
```bash
scripts/sim_e2e.sh <simulator-udid>          # e.g. the "iPhone Duo" simulator
```
